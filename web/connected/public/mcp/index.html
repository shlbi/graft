01 / THE TOOL SURFACE

Three tools.
Clear boundaries.

Repot follows MCP's tool model: the agent can discover capabilities, but the server still enforces filesystem and write boundaries.

01

repot_inspect

Read-only. Finds likely feature files, related tests/support, destination context, and warnings. No AI call.

02

repot_draft

Read-only. Optional AI turns bounded selected context into a reviewable patch. Nothing is written or executed.

03

repot_apply

Write-capable, disabled by default. Applies only a stored review and refuses stale destinations, symlinks, deletes, and path escapes.

02 / SAFETY CONTRACT

Agentic.
Not reckless.

01

Allowed roots are mandatory. Repot cannot read repositories outside the directories you explicitly expose.

02

Secrets fail closed. Common secret/generated paths are excluded and sensitive-looking selected text stops the request.

03

Writes require operator opt-in. Start read-only. Enable --allow-writes only when you want reviewed drafts to modify files.

04

No shell execution. Repot MCP does not run generated code, package managers, hooks, builds, or tests. Verification stays not_run until a separate isolated workflow actually runs it.

03 / INSTALL

Source install.
For now.

The MCP package is not published to npm yet. Install from the public Repot repository, then point your client at the local stdio server.

TERMINAL
git clone https://github.com/shlbi/graft.git repot
cd repot/mcp
npm install
npm test
npm run check
CURSOR / .cursor/mcp.json

Cursor

{
  "mcpServers": {
    "repot": {
      "type": "stdio",
      "command": "node",
      "args": [
        "/absolute/path/to/repot/mcp/server.mjs",
        "--allow-root",
        "/absolute/path/to/projects"
      ]
    }
  }
}

Keep it read-only first. Add --allow-writes only when you want the apply tool enabled.
